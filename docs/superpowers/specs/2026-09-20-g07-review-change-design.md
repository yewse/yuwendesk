# G07 审查与一处修改设计

## 目标与范围

G07 在 G05 的不可变 `LessonPlan` 修订和 G06 的三类五文件生成基础上，交付四个有序工作包：

1. G07-T01：确定性审查与可选模型审查分层，输出严格 `ReviewReport`。
2. G07-T02：把教师的一次修改表达为严格 `ChangeProposal`，按依赖图创建候选修订并只失效必要模块。
3. G07-T03：在“我的课程”提供单方案、最少选择、一次确认和差异摘要。
4. G07-T04：五文件整包暂存、校验、发布与失败回退，保留旧修订和旧成品。

本阶段不重做 G00–G06，不实现 G08 的课堂观察归因，不以模拟内容证明真实教学质量，也不关闭 Windows、真实 API、Office/WPS 保真或签名外部门。

## 不可变约束

- `ReviewReport` 与 `ChangeProposal` 必须通过仓库现有严格 Schema；不放宽 `additionalProperties:false`。
- `is_effectiveness_proof` 永远为 `false`；软件一致性通过不等于教学效果通过。
- 未执行的模型、Office/WPS、Windows 或人工专业检查必须进入 `not_executed_checks` 或外部阻断记录，不能写成 PASS。
- `LessonPlan` 修订不可原地覆盖。成功修改产生新 `revision_id`，`previous_revision_id` 指向提交时的当前修订。
- 旧修订、旧成品和哈希继续可查。外部编辑过的导出副本不自动回写内部计划。
- 同一业务请求必须持久幂等；同键异载荷拒绝，过期基础修订返回 `VERSION_CONFLICT`。
- 五文件只有全部生成、写入并核验后才允许切换当前修订；失败时当前可靠版本保持不变。
- 每个 G07 工作包独立小提交，并同步更新 `PROGRESS.md` 与 `HANDOFF.md`。

## 方案选择

采用“不可变修订 + 显式失效图 + 暂存后发布”。

不采用直接修改当前计划再导出的方式，因为文件或数据库中途失败会造成当前计划与成品不一致，也无法满足旧版保护。不引入通用事件溯源或任意 DAG 工作流引擎；G07 只实现规范列出的变更类型和 M02–M10 失效映射，避免为后续阶段预建过度抽象。

## 组件与职责

### 审查域

新增独立的审查模块，输入 `LessonPlan` 以及可选的成品清单，输出严格 `ReviewReport`。模块不读写数据库、不调用网络，因而可确定性单测。

确定性检查至少包括：

- 完整 `LessonPlan` Schema 与现有业务验证；
- 稳定 ID、目标—任务—评分—活动引用一致性；
- 活动时间顺序、声明课长和必要学生行动；
- 来源锚点的存在、版本身份和 `verification` 状态；
- 五文件角色/格式集合、计划与修订身份、哈希和角色隔离；
- 设计状态与教学效果状态分离。

每个问题包含 `rule_id`、对象 ID、证据、严重性、退回模块和验证类型。确定性硬错误为 `blocking` 或 `fix`；开放解释与专业判断使用 `teacher_review`，不因缺少预设关键词自动判错。存在开放的 `blocking` 问题时 disposition 为 `blocked`；只有 `fix` 时为 `needs_fix`；否则为 `ready_for_teacher`。

模型审查是可选层，不能覆盖确定性问题。没有授权真实调用时，报告明确列出 `model_semantic_review` 未执行；测试替身结果只标 `model_assisted` 且保留内容来源身份。Office/WPS 保真和教师专业复核同样列为未执行外部检查。

### 变更域与依赖图

渲染层不直接提交任意计划 JSON。IPC 接收受控 `LessonChangeRequest`，包含基础修订 ID、业务幂等键和以下变更之一：

- `change_duration`：改变实际课时；
- `increase_independent_time`：增加学生独立活动时间，压缩可压缩/可选活动；
- `remove_link`：按稳定联结 ID 删除联结及明确依赖项；
- `edit_task`：修改一个任务题意；
- `edit_rubric`：修改对应合理答案范围；
- `presentation_only`：仅改变字号、纸张或主题等呈现规格，不产生新的教学语义修订。

受控请求先转换为现有严格 `ChangeProposal`。`plan_revision_id` 始终表示提案所针对的基础修订；候选/已接受修订 ID 放在存储伴随元数据和 IPC 结果中，不向严格合同塞字段。G07 尚无课堂观察时，`observation_ids` 为空；`hypothesis` 明确记录“教师主动修改，不是效果归因”；`predicted_evidence` 与 `disconfirming_evidence` 描述新包应出现和不得出现的可检查差异；`status` 在预览时为 `proposed`，整包提交成功后为 `accepted`。

固定失效映射为：

| 变更 | 失效模块 | 保留内容 |
|---|---|---|
| 改课时 / 增加独立时间 | M08、M09、M10 | 已核实来源、M02/M03 事实和班级资料 |
| 删除联结 | M05、相关 M06/M07、M08、M09、M10 | 无关任务、已确认来源和班级条件 |
| 修改题意 | 相关 M07、M08、M09、M10 | 无关任务及其稳定 ID/语义 |
| 修改评分范围 | 相关 M07、M09、M10 | 原始任务和来源；历史评分版本不覆盖 |
| 仅呈现规格 | M09 格式产物、M10 成品检查 | `LessonPlan.revision_id` 和全部教学语义 |

变更应用器是纯函数：输入基础计划和受控请求，返回候选计划、差异摘要、失效模块和 `ChangeProposal`。它不能写文件或切换当前版本。课时缩短时先移除/压缩 `optional`、再处理 `compressible`，不得自动把删减内容转成作业；若核心学生行动已无法容纳，则返回阻断问题而不是只改时长数字。

### 整包发布服务

G06 的 `buildMaterialSet` 继续负责内存中的确定性五文件生成。G07 新增发布服务，替代 IPC 内当前会吞掉目录、文件和清单错误的直接写入逻辑。

发布顺序：

1. 读取并锁定当前基础修订；校验 `baseRevisionId`。
2. 检查持久幂等记录；同键同指纹返回原结果，同键异指纹拒绝。
3. 在内存中生成候选计划、差异、提案和预生成审查。
4. 生成五文件，并验证恰好包含 PPTX、学生 DOCX/PDF、教师 DOCX/PDF，全部 revision 身份和哈希一致。
5. 写入 `materials/.staging/<bundleId>`；每个文件写入后从磁盘重读并核对 SHA-256。
6. 将完整暂存目录重命名为 `materials/<revisionId>/<bundleId>`。最终目录已存在时仅在所有哈希完全一致的幂等重放中复用，否则拒绝覆盖。教学语义变更使用新 `revisionId`；仅呈现变更沿用原 `revisionId`、使用新的 `bundleId` 和呈现规格哈希。
7. 运行成品审查。存在 blocking/fix 问题时不切换当前修订。
8. 在单一 SQLite `IMMEDIATE` 事务中插入候选修订、五条成品清单、审查报告、已接受提案、幂等结果，并更新 `lesson_plan.current_revision_id`。
9. 返回新修订、差异摘要、审查报告、五文件清单和旧版提醒。

如果步骤 1–7 失败，删除暂存/未引用候选目录并保持数据库不变。如果最终目录已重命名但数据库事务失败，旧当前修订仍不变；发布服务尝试删除未引用目录，删除失败也不得把候选版本显示为当前。进程崩溃遗留的未引用目录是可清理垃圾，不是有效成品；以 SQLite 当前修订和已提交成品记录为唯一发布事实。

### 存储

新增一次 SQLite 迁移，保存：

- `review_report`：报告 ID、计划/修订 ID、严格 JSON、创建时间；
- `change_proposal`：提案 ID、计划 ID、基础/候选修订 ID、严格 JSON、请求种类、提交状态、创建/接受时间；
- `material_bundle`：包 ID、计划/语义修订 ID、呈现规格哈希、目录、发布状态和创建时间；
- `lesson_change_idempotency`：幂等键、请求指纹、状态和完整成功结果。

迁移为 `material_artifact` 增加 `bundle_id`，让同一语义修订可保留多个呈现包而不覆盖路径。`LessonStore` 新增原子 `commitLessonChange`，把候选修订（仅语义变更时）、成品包、五条成品、报告、提案、幂等结果和当前指针置于同一事务。现有历史表不删除、不重写。呈现规格变更不创建语义修订，使用同一 `revision_id` 生成新的 `bundle_id`；本工作包不把外部编辑文件导回计划。

### IPC 与界面

新增窄接口：

- `review.run(planId, revisionId?)`：读取指定修订并返回/保存审查报告；
- `change.preview(planId, baseRevisionId, change)`：纯预览，返回单一 `ChangeProposal`、受影响模块和语义差异，不写当前版本；
- `change.apply(planId, baseRevisionId, change, idempotency_key)`：执行整包发布；
- `change.history(planId)`：返回修订、提案和五文件历史，不返回任意系统文件能力。

所有 payload 进入 `schemaGate` 严格校验，拒绝多余字段、超长文本、未知枚举和缺失幂等键。预加载层只暴露命名方法，不暴露通用 invoke 或文件系统。

“我的课程”每次只呈现一套当前方案。教师选择“改变课时”“增加独立时间”“减少联结”“修改题目/答案范围”中的一项后看到一份差异摘要和受影响成品；确认一次即重建相关五文件，不要求逐文件选择模板。成功后显示旧修订仍可用，并在题号或材料改变时提醒已打印讲义需要重印或继续统一使用旧版。失败时显示旧版未受影响和可重试动作。

### 争议与降级

- 引文或来源版本冲突退回 M03，并阻断受影响交付。
- 任务题意或合理答案存在专业争议时退回 M07，状态为 `teacher_review`，不按关键词自动否定有文本依据的解释。
- 课时无法容纳核心任务时退回 M08，不新增隐性作业。
- 五文件身份、角色隔离或写盘不一致时退回 M09，旧包继续有效。
- 同一失败连续达到三次时停止自动重试，保留可靠基础版本并显示人工可处理的错误，不循环重写。
- 无真实模型时确定性审查和受控修改继续可用；真实模型语义审查保持 `BLOCKED_EXTERNAL`/未执行。

## 测试与验收

所有生产行为按 TDD 实现，先观察对应测试因缺少能力而失败。

### G07-T01

- 正常计划得到 `ready_for_teacher`，但 `is_effectiveness_proof=false`。
- 错引文、冲突来源、任务/评分/活动断链分别定位到 M03/M07/M08/M09。
- 开放解释有原文支持时产生 `teacher_review` 或无问题，不因缺少预设性格词判错。
- 未运行模型/Office/人工检查进入 `not_executed_checks`。
- 覆盖 BIZ-R046–R050、PED-003 的可机器执行部分；主观质量保持未验证。

### G07-T02

- 改课时只失效 M08–M10，来源不重导入；缩短时先压缩/删除非核心活动。
- 删除联结后相关任务、时间线和五文件无残留，无关语义保持。
- 修改题目和评分范围同步，旧答案不串入新题。
- 过期基础修订冲突；幂等重放只提交一次，同键异载荷拒绝。
- 覆盖 JOB-002、JOB-003、JOB-006、CLS-021–023、CLS-038。

### G07-T03

- 一次“增加独立时间”确认同步更新全部相关成品并显示单一差异摘要。
- 不要求逐文件重复选择；不把采用计划写成已授课或效果提升。
- 新题号完成后显示旧纸本提醒；外部副本明确不自动回写。
- 覆盖 JOB-004、CLS-027、CLS-031、CLS-039。

### G07-T04

- 对每个文件写入位置和 SQLite 提交点注入失败；任何失败都不改变当前修订和旧成品。
- 五文件缺一、哈希不符、角色泄漏或 revision 不一致均阻止发布。
- 三次相同失败后停止自动重试并交付可靠旧版，覆盖 JOB-007。
- 结构回解析验证继续执行；Windows、真实 Office/WPS、真实 API 和签名检查记录为 `BLOCKED_EXTERNAL` 或 NOT_RUN。

每包完成后运行定向测试、全部单测、typecheck、lint、`verify:contracts` 和构建。只有实际运行且退出码为 0 的项目才记录 PASS。
