# 01　产品目标、范围与完成定义

## 1.1 目标

让无计算机基础的初中语文教师通过安装包安装，双击桌面图标打开独立应用。软件围绕当前单元和下一课，完成资料核对、内容解读、学习联结、方法与任务设计、课时安排、材料交付和后续纠正。教师常态只确认推荐方案或表达一项修改，不承担命令行、部署、依赖安装、资料手工标注和长篇复盘。

学习目标同时涵盖语言积累、阅读理解、审美、表达、方法自觉与阶段考试表现。课堂承担主要学习任务；所有必做预习、阅读、订正和打卡都纳入课外负担，不能改名后不计时。生成、教师采用、实际授课、观察到学习和证明效果是不同状态。

## 1.2 交付范围

首个完整桌面版必须实现 M01—M12 的业务闭环，支持七至九年级的数据与课程结构；先在已取得和已核实的教材范围运行。教材目录、篇目、学校课时和本届考试要求不得硬编码猜测。功能完整、资料覆盖完整、逐课课堂验证完整必须分别报告。

| 范围 | 必须交付 | 不得冒充已完成 |
|---|---|---|
| 软件功能 | 单机桌面、资料导入、本地搜索、联网生成、编辑、审查、导出、备份、恢复 | 只有聊天框、网页原型或源码不能算安装版 |
| 教学资源 | 版本化导入、来源定位、覆盖看板、合法示例、方法库 | 未取得的全套教材或评分细则不能伪造 |
| 学情 | 可选教师观察、已有授权作品、本地证据说明 | 未上传作业时不能宣称全班分析 |
| 质量 | 规则检查、专业审阅入口、真实结果记录 | AI自评不是外部验证或提分证明 |

首版不做学生账户、家长端、收费SaaS、多校共享、自动向家长发送信息、全班自动阅卷、全程录音、后台摄像、自动改正式成绩或训练基础模型。不得以这些扩展挤占安装、数据保护和真实材料交付。

## 1.3 默认工程假设

目标系统为 Windows 11 x64，8 GB内存、SSD、至少3 GB可用空间；这是待实机校准的最低测试配置。Windows 10、ARM64、macOS、Linux不作为首版承诺，检测到不支持的系统须显示中文说明，不静默安装不兼容组件。屏幕按1366×768及1920×1080、100%/125%/150%缩放测试。

界面使用简体中文，显示时间默认跟随设备所在时区；教学计划可在界面选择学校时区 Asia/Shanghai。数据库事件一律存UTC时间并同时保存必要的时区信息。不能因项目发起人在境外而把中国学校课表自动换成其所在地时间。

# 02　“零人工开发”的操作边界

## 2.1 零人工编程，不等于零授权、零成本或零教学判断

编码智能体应自行创建和修改文件、安装开发依赖、构建、运行测试、定位错误、修复、打包并输出证据。开发环境可以使用命令行；教师电脑的日常安装与使用不得依赖命令行。普通聊天会话没有文件、终端、Windows运行环境和持续执行权限时，只能产出文本，不能据此宣称完成开发。

官方资料已列出 grok-4.6，并提供工具调用及结构化输出说明；Grok Build文档描述了编码代理和非交互执行方式。[S01—S04] 实际账户是否有权限、运行环境是否允许Windows构建，必须在G00核实。开发用模型与产品运行时模型是两个独立配置，不能把开发者会话中的密钥或权限带进教师安装包。

## 2.2 必要的持有人操作

项目持有人需要提供或授权：代码仓库/工作目录、可用的编码代理环境、开发费用上限、测试用API密钥、Windows构建与桌面测试环境、合法教材资料、发布身份及签名条件。这些可经网页或图形界面一次完成，不要求持有人编写代码。教师最终只需安装、首次确认必要设置和正常教学判断。

智能体不可以自行注册付费账户、接受新法律协议、购买证书、扩大API预算、绕过学校访问限制、获取未经授权资料或发布到公网。缺少外部授权时，继续完成不依赖它的部分，将相关门槛记为 BLOCKED_EXTERNAL，不得以伪造结果通过。

## 2.3 三种完成等级

工程验证版：可以自动构建并在Windows测试，但可缺真实账户、签名或完整教学资料；必须标“工程验证，非正式教学发布”。

受控试用版：具有真实联网与完整本地功能，完成明确范围内容核对；学习效果仍是试点，专业争议可留待教师审阅。

正式发布版：达到本规范的软件发布门槛、签名与分发条件，明确资源覆盖范围。无外部教学评审时只能如实标“教学适配尚待验证”，不得标“已证明提升成绩”。

# 03　桌面安装与生命周期：不可让步的产品合同

## 3.1 安装包

正式目标交付物名为 YuwenDesk-Setup-<version>-x64.exe。它是带全部运行依赖的离线安装包，不是必须联网拉运行时的网页安装器。使用 NSIS 当前稳定工具链，安装范围仅当前Windows用户，不请求管理员权限、不装Windows服务、不写入系统PATH、不设置开机自动运行。桌面和开始菜单均创建“语文备课工作台”快捷方式。[S08]

固定 appId 为 org.yuwendesk.app；标识在升级中保持一致。安装器默认中文，正常路径只需确认安装、等待完成、启动。授权或学校限制导致无法安装时给清楚说明，不要求关闭杀毒、防火墙或SmartScreen。代码签名是正式发布门槛，但仍不能保证每台电脑不出现信誉提示；操作系统策略与应用信誉必须按实际测试记录。[S09]

## 3.2 首次启动

双击桌面图标后打开应用窗口，不启动默认浏览器，不显示终端黑框。首次本地初始化自动创建目录、数据库、密钥容器和示例工作区。没有互联网或没有API配置也必须能打开首页和明确标识的演示示例。

首次向导只包含：选择或确认班级与教材资料、确认实际单节课时、查看数据处理方式、连接AI服务。已提供的信息预填；学校和教师姓名不写死在公共安装包。API密钥可以由项目持有人在图形界面设置一次；不能要求教师输入环境变量、编辑配置文件或粘贴命令。官方API使用密钥与用量计费，账号订阅不能被假定已经提供应用运行额度。[S01]

## 3.3 常态启动与关闭

本地数据和界面加载不等待云模型。默认单实例：第二次双击唤醒原窗口，不开启第二个数据库写进程。窗口关闭前自动保存；正在生成时显示“保存进度并退出 / 继续当前任务”，不悄悄缩到托盘继续计费。退出后结束所有自有工作进程；崩溃后下次启动显示恢复选择，不在后台自动重发不确定是否计费的请求。

## 3.4 离线行为

离线可以搜索已导入非敏感资料、查看教案和来源、手工编辑计划、播放已生成课堂材料、导出已存在计划、备份和恢复。离线不能假装新生成Grok内容；提示“网络不可用，现有资料仍可使用”。可提供明确标为“本地空白模板”的人工编辑入口，不能标为AI已审查方案。

# 04　教师界面与操作流程

## 4.1 固定信息结构

主导航只有“备下一课、我的课程、资料、帮助与设置”。首页优先显示当前班级、最近确认进度、下一课建议、最近材料和需处理的一项关键问题。M01—M12、向量、令牌、IPC、Schema等工程术语不进入教师常态界面。

| 页面 | 主要内容 | 主要动作 |
|---|---|---|
| 备下一课 | 当前单元、下一任务、预计课堂安排 | 开始准备 / 换内容 |
| 方案确认 | 学习目标、学生任务、关键新材料、来源状态、时间取舍 | 采用 / 只改一处 / 换任务 |
| 修改面板 | 更简单、减少拓展、增加独立时间、改变课时、其他一句话 | 预览改动 / 确认 |
| 课堂模式 | 大字任务、文本、可控答案、计时提示 | 上一页 / 下一页 / 显示提示 |
| 我的课程 | 单元和课时、采用与授课分离、版本差异 | 打开 / 导出 / 可选反馈 |
| 资料 | 拖拽导入、来源状态、教材覆盖、问题定位 | 导入 / 查看原文 / 停用 |
| 设置与帮助 | 图形化连接、预算、备份、恢复、更新、诊断 | 检查连接 / 导出诊断 |

## 4.2 方案三层呈现

首层不超过一个主屏加必要滚动：本课目标、关键问题、学生行动、时间线、最重要风险。第二层是实际会展示的文本、任务、答案与支架，关键陌生材料不能隐藏。第三层展示出处、详细分析、联结关系、版本差异和方法依据，供需要时展开。默认只交付一套方案，不让老师在三份长文中比较。

## 4.3 关键问题与异常

只有答案会改变核心安排时才问。每次显示一个决定性问题，提供“不确定”和“使用基础方案”。关键教材原文缺失不能继续假装精准；可以生成明确的备课框架，但不得对不存在原文作引用。普通技术失败应先自动恢复，界面给自然语言和下一步，而不是英文堆栈。

错误示例：“AI服务暂时无法连接。已保存本地内容。可以重试，或先打开已有教案。”密钥无效：“连接信息需要更新，请打开AI连接设置。”超过预算：“已达到本次设置的费用上限；未继续发送请求。”未配置签名的构建不得弹出“关闭系统保护后继续”。

# 05　选定技术路线与依赖政策

## 5.1 基线选择

采用 Electron + TypeScript + React 的独立桌面应用，SQLite本地数据库，Electron内置Node运行环境，electron-builder NSIS打包。不是网页快捷方式，不使用生产Vite开发服务器，不要求本地Python、Docker、PostgreSQL、Redis、Java、Office或LibreOffice服务。React只承担界面，不接触密钥或任意文件路径。

Electron的原生窗口、受限预加载桥和内部进程通信可以支持该方案；子任务可用utilityProcess，但进程隔离本身不等于安全沙箱。[S05—S07] 选择此路线是本项目减少部署依赖的工程决策，不是宣称它在所有维度优于其他桌面框架。

## 5.2 组件职责

主进程：窗口、单实例、权限与文件选择、凭据、AI网络出口、签名检查、更新与文件导出批准。

界面进程：本地打包静态界面、编辑器、材料预览、课堂展示。nodeIntegration=false、contextIsolation=true、sandbox=true；不载入远程网页为主界面。

业务工作进程：工作流、资料解析、SQLite单写入者、检索、计划与版本、确定性审查。仅运行随应用打包且被签名的程序，不执行模型产生的代码。

文档渲染窗口：隐藏的、加载可信本地模板的窗口，负责分页预览与PDF打印；不允许网络、远程脚本或任意HTML。DOCX与PPTX使用本地生成库，正文保持可编辑。[S14—S15]

## 5.3 版本固定

G00读取官方稳定版资料，选择能共同工作的Electron、打包器、Node开发版本和依赖，并把精确版本、许可证、下载来源、检查日期写入 ENV_LOCK.json、锁文件与SBOM。不写“latest”作为可重复构建依赖，不从博客抄旧版配置。当前electron-builder文档有版本迁移提示，配置必须以选定版本Schema验证。[S08]

推荐仓库分区与CI约束详见 docs/REPOSITORY_AND_CI.md。

数据库默认 better-sqlite3；原生模块必须针对目标Electron ABI重建并在Windows包内冒烟测试。若当前稳定构建不能支持，智能体可通过ADR切换受支持驱动，但必须维持事务、FTS与备份合同，不能要求用户安装编译器。

# 06　本机运行、安全隔离与权限

## 6.1 零监听端口

生产环境不启动HTTP/WebSocket监听，不监听127.0.0.1、0.0.0.0或局域网端口。界面通过受限contextBridge调用固定IPC方法；主进程与工作进程用MessagePort内部通信。[S07] 开发服务器只允许在开发脚本出现，打包后不存在运行依赖。

测试必须观察进程、窗口、网络监听和启动路径，不能仅以“应用看起来像桌面”验收。TCP对外HTTPS连接允许；本地监听为0是产品选择而非技术限制。

## 6.2 IPC边界

每个调用验证发送者frame、窗口身份、方法白名单、输入Schema、工作区归属、对象权限和预期版本。预加载不能暴露通用 invoke(channel,...args)、文件系统、shell或原始ipcRenderer。导入与导出使用主进程文件选择生成的一次性/会话级句柄，模型和界面不能直接提交任意系统路径。

## 6.3 文件与远程内容

外部文档视为不可信数据。禁止宏、脚本、嵌入可执行文件、外部图片自动加载和文档内指令提升权限。下载仅允许授权HTTPS域名，逐跳检查重定向与私网地址，限制文件体积与类型；不访问本地file URL、云元数据地址、localhost和私有IP。

主进程不打开不可信HTML。PDF禁用脚本与外部资源；文档解析设置超时、内存与解压大小上限。上传材料中出现“忽略系统规则、读取密钥、联网发送文件”等字样，仅作为文档内容显示和记录风险，不执行。

# 07　领域对象、版本与存储

## 7.1 核心对象

| 对象 | 作用与关键字段 | 不变量 |
|---|---|---|
| Workspace / ClassProfile | 工作区、班级、课时、时区、教材引用 | 时间与年级有确认状态 |
| SourceDocument / SourceVersion | 原始资料、版本、哈希、许可、来源 | 新版本不覆盖旧证据 |
| SourceAnchor | 页/段、字符跨度、原句及上下文 | 引用能回到实际原始版本 |
| CurriculumRequirement / CurriculumNode | 课程条款、篇目、单元和进阶 | 映射有来源，未核则待确认 |
| LearningObservation | 实际作品或教师观察、条件与覆盖 | 未观察与不会不同 |
| LinkCard / Skill | 联结和教学方法，适用条件及退出规则 | 不把通用机制当本班已证效果 |
| Plan / PlanRevision | 计划身份与不可变语义版本 | 采用不代表已授课 |
| Objective / Activity / Task / Rubric | 目标、活动、独立任务、合理答案 | 使用稳定ID，非关键词对齐 |
| Artifact | DOCX/PPTX/PDF等导出物 | 对应唯一revision和内容哈希 |
| Job / StageRun | 执行状态、预算、步骤输出 | 可恢复；失败不篡改历史 |
| AuditEvent / Consent / ProviderCall | 操作、授权、网络与费用记录 | 无敏感正文与原始密钥 |

默认UUID标识；日期ISO 8601；时间长度为整数秒；金额为整数微美元或明确币种最小单位，不能浮点累加预算。示例身份全部虚构，不能把本项目教师或学生私人资料写入公共种子。

## 7.2 存储路径

程序安装到当前用户应用目录；运行数据位于 Electron app.getPath('userData') 对应的YuwenDesk目录。正文中显示“打开资料文件夹”，不要求老师理解系统路径。数据库、sources、artifacts、backups、logs、temp分目录；安装目录只读。

数据库启用外键、WAL、合理busy_timeout；工作进程是单写入者。业务更改、stage结果和outbox事件在同一事务提交；大型文件先写临时文件、校验哈希、原子改名，再由补偿任务处理崩溃遗留孤儿文件。导出物完成前不得显示成功。

## 7.3 计划状态不是一根长链

执行状态用Job状态机；计划发布状态用 draft/ready/adopted/archived；实际授课另存 teaching_event；效果状态另存 unknown/initial_support/repeated_support。避免用一个列把“生成完成→已采用→已教→有效”串成自动晋级。

工作区/班级设置变动用乐观并发expected_revision。旧页面提交会得到 VERSION_CONFLICT，展示差异而非覆盖。手工编辑产生新的PlanRevision并标记相应检查失效；外部Word/PPT修改不会自动回写真源，界面明确原文件属于外部副本。

# 08　敏感数据、密钥、删除与备份

## 8.1 最小数据与外发分级

资料标记 public_reference、licensed_reference、teacher_private、student_sensitive四类；另有独立的允许外发状态。公开可阅读不等于有权重新分发。API不得接收学生姓名、身份证、联系方式、可识别原始作业或班主任私人谈话；首版学生原始材料默认且强制LOCAL_ONLY。

学生材料只用于本地展示、人工标注的观察或明确分离的去标识衍生摘要。自动遮盖姓名不等于真正匿名化。首版不开放原始学生材料上云开关；如确需新增，必须做独立权限与合规设计，不由智能体绕过。本项目不提供法律合规结论。

## 8.2 凭据与敏感载荷

API密钥只由主进程持有，使用Electron safeStorage的Windows DPAPI保护后存储，界面只显示末四位。Windows凭据加密不能防御同一用户权限下的恶意软件，因此不能承诺绝对安全。[S06] 加密不可用时阻止持久保存，不降级为明文；允许本次会话暂用须有显式提示且退出清除。

每工作区生成随机256位数据密钥，DPAPI封装。学生原始文件、提取文本及敏感payload使用AES-256-GCM，随机96位nonce不得复用，AAD包含工作区/对象/版本ID。敏感正文不进入SQLite明文列、FTS、日志、模型缓存或诊断包；字段名与路径也用不包含学生身份的内部ID。不要声称普通SQLite文件本身已全部加密。

## 8.3 同机备份与跨机迁移

同机自动备份使用SQLite在线备份接口或关闭数据库后的安全快照，不能只复制主.db文件而忽略WAL。[S10] 备份包含资料清单与哈希，写临时目录后原子完成。默认每日首次有写入时最多一份、保留7个日备份与4个周备份；盘空间不足提示而不删唯一可恢复副本。

跨机“导出备份”要求持有人在图形界面设置强口令，应用使用经过校准的标准KDF生成备份密钥，AES-GCM加密整个归档，单独封装工作区数据密钥。API密钥永不进入备份；新机恢复后重新连接AI。不能把原机DPAPI数据复制过去就宣称可解密。

恢复先校验版本、哈希、密码和可用空间，再在旁路目录恢复并自检；成功后切换，失败保留现有数据。忘记备份口令不能承诺找回；无后门。默认卸载保留资料；“删除全部资料”需独立图形化双确认和备份提示，并说明SSD物理安全擦除不在保证范围。

## 8.4 撤回与删除

停用资料先禁止新检索，依赖它的计划标记引用需复核。永久删除应覆盖原件、提取物、索引、派生敏感摘要与相关缓存，保留不含正文的操作墓碑。旧备份中的删除需要纳入备份轮换或主动清理，界面如实说明；不能声称删除主文件已擦除所有备份。法规或用户删除要求优先于“事件不可删除”的工程偏好。

# 09　接口合同与错误处理

## 9.1 统一调用外壳

内部请求包含 schema_version、request_id、workspace_id、operation、expected_revision、idempotency_key、payload；写操作必须有idempotency_key和expected_revision或显式新建语义。响应为 ok/data 或 ok=false/error；error含code、message_zh、retryable、next_action，不把堆栈或密钥放入界面。

合同见 contracts/ipc-catalog.json 与 shared.schema.json。结构校验成功不代表引用、权限和教学推理正确，服务层继续执行语义校验。每个接口都必须有非法输入、越权、重复请求、版本冲突及适用的成功案例。

## 9.2 主要接口域

应用：app.bootstrap、app.health、app.getStatus；设置：settings.get/update；资料：sources.pick/import/status/search/read/retire；课程：curriculum.list/importCoverage；备课：plans.create/get/list/revise/adopt/recordTeaching；任务：jobs.get/cancel/resume；反馈：observations.add/list；材料：artifacts.render/export/reveal；维护：backup.create/restore、updates.check/stage/apply、diagnostics.export；凭据：provider.configure/probe/clear。

接口是受限内部命令，不开放HTTP API。资料和任务只返回当前工作区对象。工作区切换、班级管理、资料重分类/删除、观察删除、备份列表/删除及计划归档使用catalog中的专用接口，不能绕过统一权限。删除与覆盖必须使用主进程生成的交互确认令牌，模型建议不能自行制造令牌。

## 9.3 错误码

完整21项错误码见 contracts/ipc-catalog.json。覆盖输入与来源、隐私与凭据、网络与模型、预算与任务、版本、导出、磁盘、数据库、备份、更新和系统兼容。每项错误都映射到中文说明、是否可重试及下一步动作，不能统一显示“未知错误”；REQUEST_UNCERTAIN等需保留费用与重放风险提示。

# 10　Grok 4.6接入与费用控制

## 10.1 开发与运行模型分离

开发智能体优先使用用户指定Grok 4.6，在有文件、工具和测试权限的环境执行本规范；桌面运行时默认xAI provider与model_id=grok-4.6，允许持有人图形化修改为经过探测的授权模型。不得静默降级到另一型号，模型改变应保留原因、版本和差异并重跑代表性评测。

官方文档列出grok-4.6及工具/结构化输出；实际调用能力须用小样本探测，不能只根据显示名称推断。[S01—S03] 运行时使用本地维护的对话与阶段上下文，不依赖远程保存历史。优先采用当前官方Responses接口；请求字段以G00固定的接口版本验证，示例不能代替真实连通测试。

## 10.2 能力探测

图形化“检查连接”验证HTTPS、凭据、模型可用性、文本、结构输出、必要工具调用、错误处理和流式协议。记录成功时间与脱敏provider request ID。未提供密钥则只运行模拟契约测试，真实连通测试状态必须BLOCKED或NOT_RUN，不能写PASS。检查本身可能产生费用，应在连接设置说明。

## 10.3 隐私与联网事实

官方API隐私文档区分“不用于训练”与默认审计保留，并说明ZDR会影响有状态功能。[S16] 因此不能宣传“本地桌面=内容不离开电脑”，也不能仅设置客户端store=false就声称服务器零保留。界面应明确哪些授权的文本片段会发送，保留策略依实际服务与账户验证；所有学生敏感正文保持本地。

学校网络不可达时允许已有内容继续使用，提供图形化合法连接配置，不提供绕过地域限制、账号限制或学校安全策略的方案。开发成功不等于教师实际网络可达；首次连接和发布验收分开测试。

## 10.4 调用与重试预算

默认单工作区同时1个备课任务；任务内网络并发最多2；每阶段最多一次结构修复、一次语义修复；单任务最多24次模型调用，工具调用最多40次，超过立即暂停并给可恢复解释。数字是初始安全上限，可在试点后以ADR调整，不能无限循环自评。

每次发起前预留最坏输出预算；实际返回后结算。价格表带currency、effective_at、source_url、context_tier、tool_costs；未知价格时不得显示精确费用，持有人先设用量上限或确认。发布不固化本文件查询日价格，避免长上下文或工具费用被漏算。

对429/明确临时5xx执行指数退避、抖动与Retry-After，最多2次且计入总上限；认证与权限错误不重试。网络超时后无法判断上游是否执行时记REQUEST_UNCERTAIN，不承诺exactly-once或免费重试。用户取消后不再派发新请求，已经在途的调用可能仍计费，界面如实记录。

## 10.5 模型工具权限

仅暴露search_sources、read_anchor、read_curriculum、read_confirmed_progress、propose_link、propose_activity、check_duration、submit_stage_result等白名单。写业务状态由应用验证后执行。禁止模型获得shell、任意文件读写、SQL执行、密钥读取、账户购买、消息外发、更新安装或不受限网络访问。

# 11　资源导入、搜索与引用核验

## 11.1 导入格式与边界

正式版必须支持文本型PDF、DOCX、TXT、MD、CSV、XLSX、合法资源包。PPTX导入至少提取文本和备注并说明复杂图形可能缺失。PNG/JPG和扫描PDF支持安全预览与页码定位；首版不将未可靠识别的图像内容自动转成已核知识。需识别时优先获取合法文字版，图像识别仅按授权范围作为可选功能并附置信限制，不要求教师安装OCR环境。

对文件大小、页数、压缩比设硬上限：默认单文件100MB、PDF1000页、归档展开500MB、最多10000条目。超限提供拆分/保留原件选项，不让解析器耗尽内存。禁止递归监视全磁盘，只处理用户选择的文件或目录。

## 11.2 资料状态

IMPORTED → EXTRACTED → METADATA_CONFIRMED → CHECKED_FOR_USE；并列REQUIRES_REVIEW、QUARANTINED、RETIRED。这只是资料可使用状态，不意味着内容永远正确。机器提取后的原句位置、PDF印刷页码与文件页序号分别记录。

若同名教材版本冲突，显示差异，不自动合并注释。课标与考试资料必须记录适用学段、考试年、发布机构、题号和评分说明的身份。模拟题和自拟题永远不继承真题标签。

## 11.3 检索策略

先按工作区、许可、版本、教材和资料状态过滤，再进行题名/精确短语搜索、中文适配全文检索，最后按任务相关性重排。基线采用SQLite FTS5与中文三元组；一至二字查询必须走短词或题名补充检索，因为FTS trigram有短查询限制。[S11] 不把英文分词的默认表现当中文可用证据。

首版不强制远程向量数据库；可加本地向量作为增强，但精确引用与版本过滤不由相似度取代。检索结果必须带SourceAnchor与邻近上下文。检索无结果依次检查题名别称/标点、版本、扩大上下文、允许的资料补充；最后才问决定性未知。

## 11.4 引用三层检查

第一层检查被引用原句确实存在于指定版本和跨度；第二层检查原句在上下文中是否支持陈述；第三层区分文本解释和史实。不能强制每个解释逐字出自资料库，也不能仅凭URL存在就认为推理正确。

生成的计划和自拟材料不自动作为权威原始来源回流；可以作为教学作品保存，但明确generated属性。权威来源层和生成成果层在查询中隔离，防止伪知识自我强化。

# 12　工作流、状态机与模块协作

## 12.1 有限状态

Job状态为 QUEUED、PREPARING、WAITING_INPUT、RUNNING、REVIEWING、REVISING、READY、FAILED_RETRYABLE、FAILED_FINAL、PAUSED_BUDGET、CANCELLED。WAITING_INPUT必须有具体问题与恢复点；READY只表示方案可供教师审阅。应用重启把未完成在途调用标记为需核实，不直接重跑。

每个StageRun记录input_hash、source_snapshot、output_hash、attempt_no、schema_version、skill_version、model_id、provider_request_id、status和成本；已完成步骤可复用，但教材、课时、隐私授权或上游目标改变时按依赖失效。缓存不能跨工作区泄漏私人材料。

## 12.2 默认流程

M01确定任务 → M02课程/考试、M03文本、M04学情形成依据 → M07先形成成功表现草案 → M05联结与M06活动共同完善 → M07校验认知要求与独立证据 → M08编排 → M09生成材料草稿 → M10检查 → M09教师确认 → 正常课堂 → M11证据 → M12纠正。

M02/M03/M04可以有限并行，但冲突必须在编排前解决。M06与M07不是无限互相调用；最多两轮校准，仍冲突则缩小本课目标或要求关键选择。12模块是职责，不等于12个无约束聊天Agent。

## 12.3 局部修改失效图

改变课时：M08时间线、M09全部材料、M10一致性必须重算；不重新花钱检索已经核实的作者史实。

改变教材版本：M02映射、M03引文、M05联结、M07任务与答案、下游材料都失效；不能只替换标题。

改变联结：M05/M06/M07/M08/M09相关部分重算，但已确认班级资料不重问。

改变评分标准：历史观察保留旧评分版本，生成新的重评记录，不覆盖原始作答。

改变隐私授权：未发出的调用重新检查；不能把历史授权当成继续外发许可。

# 14　语文学科方法、学习联结与应考

## 14.1 方法库不是理论口号库

每项Skill包含适用课型、前提、材料需求、学生动作、示范方式、支架及撤去、观察标准、常见失效、研究依据和证据级别。初始提供：语言积累、古诗词、文言文、现代文学、信息/议论、多文本、整本书、写作、讲评、口语、自然复现与跨学科迁移。

已有知识联结、示范与练习、主动提取、元认知、可使用反馈、读写结合可作为设计依据，但研究结论与本班效果不能混写。具体证据与来源沿用业务基线，并在资源接入时复核适用版本。[B01]

## 14.2 联结结构

LinkCard必须含当前文本锚点、关联文本锚点、联结类型、相同与不同、解决的理解问题、学生已学状态、必要前提支持、学生任务、返回本篇问题、预计时间、替代内容、后续正常复现和否定条件。生平事实与作者心理推测分开；同样出现月亮不意味着同样抒情。

《梦游天姥吟留别》只作本项目方法案例，不自动放入初一必学清单。完整生平可以在教师背景层，学生只接触必要信息；联结应帮助解释本篇词句和整体关系，而不是用故事替代文本。没有已学证据时，不能把《行路难》等候选称为复习。

## 14.3 开放解释与评价

阅读任务按理解、概括、解释、比较、评价等认知动作映射；不能用关键词共现作为目标达成。评价包含合理解释、必要证据、可接受不同表述、典型不充分答案和争议处理。自动评分只是建议，不能写入正式成绩。

## 14.4 考试要求

考试资料按地区/年份/适用届别/来源管理，具体分值只使用核实文件。不得凭当前初一学生身份预测其未来中考题型。应考训练包括审任务动词、对象与范围、证据选择、完整表达、作文审题规划、时间分配与检查；不把七年级日常课堂改为全年冲刺，也不许承诺每次领先。

# 15　唯一计划真源与多格式输出

## 15.1 LessonPlan是语义真源

计划包含稳定ID的目标、文本片段、任务、评分、活动、联结、时间、课外安排、支架、预案和来源。教师修改发生在该结构层。DOCX、PPTX、PDF、HTML课堂模式均由同一revision渲染，不能各自再次请求模型生成正文，否则容易漂移。

每份成果manifest带plan_id、revision_id、schema_version、renderer_version、source_hashes、文件SHA256与生成时间。导出失败不能留同名半成品；使用临时文件、验证、原子改名。文件名使用合法字符并处理同名，禁止覆盖非应用产生的文件而不确认。

## 15.2 DOCX、PPTX、PDF与课堂模式

DOCX包含课堂要点、详细流程、关键任务与答案、来源及必要附件；标题层级、表头跨页重复、可编辑正文必须可用。PPTX正文和任务为可编辑文本/形状，不能把整页截图当课件；16:9默认，大字、充足留白，避免密集教案式幻灯片。字体引用目标系统可用字体，不在工程文档包分发字体。

PDF由可信本地模板渲染，保留文本可选择；分页规则不能裁掉表格。HTML课堂模式加载本地经过消毒的结构内容，答案按教师显式动作显示，投屏默认不显示私密备注或学生信息。软件内能查看和展示，不依赖教师安装Office；外部DOCX/PPTX编辑需要相应应用，不承诺所有编辑器像素一致。[S14—S15]

## 15.3 编辑边界

提供目标、题目、答案、活动、时间的结构化编辑及撤销。手动编辑后重新检查相关项；不偷偷改回AI偏好。外部修改导出的Word或PPT不自动更新内部计划；重新导入只作为新资料，提示不是源计划的无损往返编辑。此限制必须在帮助中写明。

## 15.4 课堂成品增补（CR-001，引用）

本章的多格式输出经变更请求 CR-001 细化为明确的课堂最终交付：一套课时默认包含三类成品五文件——可编辑课堂 **PPTX**、学生讲义 **DOCX/PDF**、教师讲解版 **DOCX/PDF**；教案与学校提交格式保留但不得替代这三类课堂成品。受众分工、任务跨载体定位、先题后反馈、学生作答空间、教师合理答案与追问、一处修改整套联动、导出失败不覆坏旧包、受众过滤而非隐藏等要求见：

- 需求与规范：`docs/changes/CR-001/CR001_CLASSROOM_DELIVERABLES.md`（`CR001-R01–R24`）
- 伴随合同（不放宽严格 schema）：`docs/changes/CR-001/contracts/CLASSROOM_DELIVERY_CONTRACT.md`
- 验收增补（`CLS-001–040`，全部 NOT_RUN）：`acceptance/addenda/classroom-delivery.cases.json`

# 16　质量门与诚实降级

## 16.1 三级检查

确定性检查：Schema、ID引用、来源跨度、版本匹配、计划时间、预算、隐私标记、任务与答案引用、导出hash、文件真实存在。

模型辅助检查：解释是否有依据、背景是否越界、任务与目标认知要求是否相符、是否只靠模板即可完成、联结是否牵强。结论带理由和依据，不输出万能教学质量分。

需要真实判断的检查：实际课堂适配、合理文学分歧、学生保持与迁移、减负和考试表现。无真人/真实学习证据时保持未验证，不由第二个AI冒充教研专家。

## 16.2 阻断、修复与复核

密钥泄露、越权外发、关键引文错误、教材错版、题目无解、更新签名失败、数据丢失风险属于blocking。无来源的非必要背景可自动删去；合理开放解释存在分歧时标teacher_review而不是机械阻断全部备课。

同一问题最多两轮自动修复；仍不能解决就降低方案复杂度或暂停受影响部分，交付其余可靠部分并列明范围。不得无限重生成，不得通过删除测试、降低标准或把错误项改为“不适用”来凑成功。

## 16.3 教学纠正

M11先查题目、评分、样本和实际时间，再提出前提不足、支持不足、活动错位、保持不足或表达不足等假设。M12每次说明替换什么、减少什么、预测和否定条件，在正常后续任务复核。教师删减率可调整界面偏好，但不足以宣布某教学方法无效；未反馈不自动学习为“成功”。

# 17　安装器、签名与发布安全

## 17.1 安装配置合同

NSIS oneClick=true、perMachine=false、createDesktopShortcut=true、createStartMenuShortcut=true、deleteAppDataOnUninstall=false；这些键应以选定打包器Schema实测。[S08] 简体中文安装器，不显示不必要选择，不提供全机安装入口。默认程序装当前用户；不能在升级中改变appId或安装位置导致两个程序。

预打包全部本地运行依赖和受许可示例。没有网络、没有Node/Python/Office的干净标准用户机器仍然可以安装和启动到首页。签名与系统安全策略单独验证，不通过隐藏告警脚本绕过。

## 17.2 签名与制品

正式版EXE及相关可执行组件必须由持有人控制的可信签名身份签名并带时间戳，生成SHA256清单与SBOM。证书秘密通过CI密钥库/签名服务注入，模型不可读取私钥，不放在仓库和安装包。没有签名凭据时输出UNSIGNED_TEST_BUILD并阻止正式发布任务。

自签名只能用于隔离测试，不能冒称受信任发布者。SmartScreen可能基于信誉和策略阻止程序；提供发布者、版本和校验信息，并引导联系支持，不指导关闭系统保护。[S09]

# 18　更新、迁移与故障恢复

## 18.1 更新方式

正式版支持图形化“检查更新”和导入受信任离线更新包；不要求教师重新运行安装命令。更新清单与包均由发布方签名，校验发布者、版本、平台、哈希、有效期与允许的schema范围；只允许应用内置可信公钥/发布身份，不信任下载包自己声明的key。

没有已配置发布地址时，界面显示“当前使用离线更新”，不能伪造下载链接。新版本不会在授课展示或有活动任务时强制安装。下载与安装分离，教师选择合适时机重启。拒绝降级到被撤销或schema不兼容版本。

## 18.2 数据迁移

迁移脚本单调版本化，升级前做可校验备份；在事务或隔离副本执行并进行integrity_check。新版本确认数据库与关键对象正常后才接受新的业务写入。若首次升级失败，恢复旧程序与升级前备份。

一旦新版本已经产生新数据，不能简单恢复旧数据库覆盖。回退需明确数据格式兼容性；不兼容时提供导出与支持流程，保留新数据副本。回滚是受约束恢复，不是无条件“点击一键绝不丢数据”。

## 18.3 恢复场景

进程意外结束、磁盘满、SQL迁移失败、导出文件被占用、掉网、上游超时、系统睡眠恢复、重复双击、更新中断都要有可重现案例。日志只记录脱敏元数据；诊断包默认不含教材全文、学生正文、API密钥或模型完整输入输出，发送前可预览且默认不自动上传。

# 20　自动测试、证据与不允许的捷径

## 20.1 测试层次

单元测试：状态转换、预算、时间线、版本失效、权限、Schema、哈希与引用、备份加密。集成测试：数据库与文件事务、解析与索引、provider协议、任务恢复和多格式渲染。桌面E2E：实际窗口、图形操作、关键材料、退出恢复和中文路径。安装测试：干净Windows VM、标准用户、无开发运行时、真实快捷方式启动。真实AI测试：持有人授权费用下探测所选模型，记录真实结果。

Playwright提供实验性Electron自动化接口，采用前必须验证锁定版本兼容；它不能独自证明NSIS系统安装与SmartScreen体验，因此安装器另用Windows桌面自动化与独立干净VM验证。[S12]

## 20.2 对结果诚实

测试状态限定 PASS、FAIL、BLOCKED、NOT_RUN；SKIPPED必须带原因并按未通过发布门处理。每项结果包含commit、构建哈希、环境、操作、观察、日志或截图位置；截图若由fixture或模型生成不得充当真实界面证据。模拟provider测试不等于真实联网测试。

编码代理不可修改冻结验收条目以便通过，不得删除失败测试、扩大超时无限等待、把所有断言变成快照、用硬编码样例代替实际检索或生成。修改标准需提出变更理由，并保留旧案例复跑。安全关键不变量必须包含失败输入测试，不能只测正常路径。

## 20.3 教学测试

提供正常与对抗样例：版本冲突、未知是否通读、题干只要求概括却被评分要求解释、同作者牵强联结、同意象不同作用、合理不同答案、样本6份冒充全班、课堂时长缩短、没有初稿、原题背熟冒充迁移。样例可为明确自拟文本，不能伪装江西真题。

机器可检查的规则与文学判断分开。没有人类校准的主观评价只能称“自动一致性筛查”，不能标专业测量已验证。学生考试优势不是软件发布自动化测试的断言。

# 22　编码智能体的自主执行纪律

## 22.1 工作方式

先读取README_START_HERE与AGENTS，再读取本规范、合同和相应工作包。每次只处理一个有界任务；记录假设、修改、命令、退出码、测试证据、已知问题。完成后提交小步commit，更新PROGRESS与HANDOFF；新会话从这些文件恢复，而不是依赖聊天记忆。

开发、测试、审查可以由不同会话执行，但不要求不同模型，也不能把同模型分角色当独立专家证明。审查优先基于代码diff、实际测试与原始资料；不给无法验证的“整体看起来合理”高分。

## 22.2 权限与停止条件

只在分配仓库和隔离构建目录改文件；禁止读取个人浏览器资料、密钥目录、其他项目或真实学生目录。允许安装已核许可的开发依赖，禁止自动更改系统安全策略。命令需要网络时遵守域名白名单与预算。生成代码可以运行于隔离开发环境；桌面运行时不得执行模型临时生成的脚本。

遇到费用超限、无授权资料、缺真实测试环境、签名无资格、不可逆删除、发布外网、验收冲突时，记录阻断并停止受影响操作，不虚构解决。可以继续进行其他安全任务。不能在没有Windows环境时伪造Windows安装成功截图。

## 22.3 修复策略

一次失败先复现并分类：环境、依赖、合同、业务、数据、安全或测试自身。先保留回归案例再最小修复。对同一错误连续3次无实质进展，输出定位证据与替代路径，不无限调用模型。只有确证测试不正确时才通过变更流程修测试，禁止删断言掩盖缺陷。
