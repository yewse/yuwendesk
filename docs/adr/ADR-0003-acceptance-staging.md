# ADR-0003 G01 与后续功能的验收分期修正

- 状态：已接受
- 日期：2026-09-19
- 阶段：PR#1 续开发（F07）

## 背景

原分期把 INS-001..006 全部挂在 G01，且把"无本地监听"INS-008 放到 G09。审查指出两点需澄清（但不得删除或降低任何完整验收要求）：

1. G01 的"可安装"存在两个不同层级：**Linux 上的工程验证构建** 与 **干净 Win11 普通用户实机安装验收**。二者证据不可互相替代。
2. 生产安全不变量（尤其 INS-008 无 HTTP/WebSocket 监听，P0）应从 G01 起即在每次构建持续验证，而非推迟到 G09 才首次检查。

## 决策

1. 明确四条证据线，任一不得替代其它，各自独立记录状态（详见 `reports/WINDOWS_BUILD.md`）：
   - ① Windows 自动构建（未签名安装包）
   - ② 干净 Win11 普通用户安装验收（INS-001..006 的实机部分）
   - ③ 正式代码签名（受信任发布者，S13）
   - ④ 真实 Grok 连通/能力探测（G04）
2. 在 `planning/work-packages.json` 的 G01-T03 追加 INS-008 到 `acceptance_ids`（自 G01 起验证无本地监听），**保留** 其在 G09 的验收，不删除、不降低阈值。
3. G01 标记为"工程验证 PASS（Linux）"与"实机安装 NOT_RUN/BLOCKED_EXTERNAL"两个并列状态；证据报告不得用工程验证冒充实机验收。
4. `acceptance/cases.json`（冻结验收基线）保持不变；本次仅在 planning 层做追加式分期澄清与新增 ADR，不改写冻结用例、不降低完整验收要求。

## 后果

- 安全不变量更早、更持续地被验证，降低"开发机能跑、教师机不安全/装不上"的风险。
- 完整验收要求（含真实 Windows 实机、签名、Grok 连通）保持不变，只是分期与证据边界更清晰。
