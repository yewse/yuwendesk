# ADR-0005：产品运行模型改为可配置服务商，不绑定 Grok

- 状态：Accepted
- 日期：2026-09-19
- 关联：ENGINEERING_SPEC §10（模型接入与费用控制）、G04 模型调用闭环

## 背景

原规范把产品运行时模型固定为 xAI/Grok（`model_id=grok-4.6`）。经决策调整：产品运行模型不应绑定单一厂商。

## 决策

1. **产品运行时模型不绑定 Grok**，改为“可配置服务商 + 实际模型 ID”。
2. **主力候选为 DeepSeek**（高性价比云模型），按官方文档默认 `model_id=deepseek-flash`；其真实能力、账户权限、参数与费用以接入时验证为准。
3. 其他服务商为可配置选择；**首版只需完成一个主力模型的可靠适配**，不要求覆盖所有厂商。
4. **开发智能体（写代码用）的选型与产品运行时模型分开**，互不带入密钥或权限。
5. **不得静默换模型、换服务商或扩大外发范围**；模型/服务商变更须显式配置并保留原因、版本、差异，重跑代表性评测。
6. 无真实账户时，用**明确标注的测试替身**完成本地链路；真实联网调用保持 BLOCKED/未验证，不伪造通过。
7. 数据、检索与业务保持本地；模型经授权云 API 调用；不新增远程向量数据库。安全、授权与预算边界不变。

## 实现映射（G04）

- `src/main/model/providers.ts`：`test-double`（本机确定性、明标非真实）与 `deepseek`（默认 `deepseek-flash`，真实联网未授权→BLOCKED）。
- `src/main/model/prompt.ts`：提示词工程作为正式能力（稳定原则/任务模板/学科方法/正反例/输出合同，`PROMPT_VERSION` 版本化）。
- `src/main/model/service.ts`：配置/探测/密钥保护(safeStorage)/预算/上下文边界(版本·权限·引用、仅获准片段、私有不外发)/缓存(不重复生成)/取消·超时·重试/结果持久化(记模型·提示·参数·材料版本)/重启不确定态。
- 迁移 v6：`model_config`、`model_job`。

## 说明

本 ADR 为决策记录，不新增需求包；既有 60 条需求、CR-001、F01–F08、R3 编号不变。历史评审/报告中出现的 Grok 字样为当时记录，不再作为运行时默认要求。
