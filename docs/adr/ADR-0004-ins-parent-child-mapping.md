# ADR-0004 INS 父子验收映射与分期依赖

- 状态：已接受
- 日期：2026-09-19
- 阶段：PR#1 二次审查续开发（原文件第 3 节 + F08）

## 背景

二次审查指出：`acceptance/cases.json` 的 INS-004 含真实导入/导出、INS-005 含真实课程/来源留存，这些依赖后续 G02/G03/G06/G07；而工作包把 INS-001..006 整体挂在 G01，易造成"G01 骨架子项通过就写父项 PASS"的误判。ADR-0003 仅区分了工程验证 vs 实机并追加 INS-008，尚未明确 INS-004/INS-005 的子项依赖。

## 决策

1. 建立 `planning/ins-acceptance-mapping.json`：为每个 INS 父项拆分子项，标注 scope（G01 / G01-实机 / 后续模块 / G10）与状态。
2. **父项在其所有子项通过前不得整体 PASS**；G01 阶段最多给出 PARTIAL，并如实标注 `BLOCKED_EXTERNAL`（实机）与 `NOT_RUN_DEPENDS_LATER`（依赖后续模块）。
3. INS-004 的真实资料导入/导出（INS-004b）在 G03/G06 实现后回归；INS-005 的真实课程/来源留存（INS-005b）在资料/课程模块实现后回归。二者当前不得包装成"已开放"。
4. INS-008 以系统级证据（进程/监听套接字）为准，界面状态面板不替代该证据。
5. 保留 `acceptance/cases.json` 冻结用例不删除、不放宽；G11 仍执行全量端到端验收。

## 后果

- 证据分期清晰：Linux 工程验证、干净 Win11 实机、后续模块回归、正式签名、真实 Grok 五类互不替代。
- 避免"骨架通过=父项 PASS"的夸大；父项状态可随子项逐步收敛。
