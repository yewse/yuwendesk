# ADR-0005 CR-001 课堂 PPT 与讲义需求增补（归档接入）

- 状态：已接受（仅需求归档 + 合同变更计划 + 工作/验收映射；功能未实现）
- 日期：2026-09-19
- 基线：PR #1 @ cffcd59

## 背景

用户提出 CR-001：备课工作台的最终课堂交付正式明确为三类成品五文件——可编辑课堂 **PPTX**、学生讲义 **DOCX/PDF**、教师讲解版 **DOCX/PDF**。教案与学校提交格式保留，但不得替代这三类课堂成品。这是独立业务变更，不重编 F01–F08、R3 或原 60 条需求。

## 决策

1. **独立命名空间**：需求用 `CR001-R01–R24`，验收用 `CLS-001–040`；**不重编号** R001–R060 / F01–F08 / R3-01–05，不改写冻结的 `acceptance/cases.json`。
2. **归档位置**：完整包归档 `docs/changes/CR-001/`；接入路径 `docs/changes/CR001_CLASSROOM_DELIVERABLES.md`、`planning/changes/CR001/{requirements,work-items,traceability}.json`、新增验收 `acceptance/addenda/classroom-delivery.cases.json`（与冻结用例分离，由总验收索引加载）。
3. **严格合同不放宽**：现有 `ArtifactManifest`/`LessonPlan` 的 `additionalProperties:false` 不得为新字段关闭；受众/角色/呈现规格/整包完成度通过独立伴随合同或受控版本升级表达（见 `docs/changes/CR-001/contracts/CLASSROOM_DELIVERY_CONTRACT.md`）。不另建独立生成三份正文的流程。
4. **实现阶段**：细化落在 **G05–G07**（映射 G06-T01..T04、G07-T02/T03），在 **G09/G11** 回归受众隔离与整包安全；**不塞进 G00/G01**，不扩展现有安装骨架，不改变原安装/安全/外部授权门。
5. **状态如实**：本轮仅"需求已归档 / 合同待实现 / 功能未实现"。CLS-001–040 全部 **NOT_RUN**，直到真实执行（真实 PPTX/DOCX/PDF + 角色清单 + 计划哈希 + 渲染/打开/编辑证据）。文档检查通过 ≠ 功能已完成。
6. **授权不变**：本 CR 不构成公开工件上传、手动触发上传、扩大费用或合并 PR 的授权；现有暂停控制保留。

## 重点落实项（实现阶段的验收要点）

同源单一计划版本；三类受众分工与目录/入口隔离；任务跨载体稳定 ID 定位；先题后反馈；学生真实作答空间；教师合理答案范围与追问；一处修改整套联动 + 旧版保护；导出部分失败原子性（不覆坏旧包）；受众过滤而非隐藏（载荷+可视双检）；离线/无 Office 本地展示。

## 后果

- 课堂最终交付定义清晰且可追踪，同时严格保持既有阶段门与冻结验收。
- 新增能力在前提满足的 G05–G07 才实现；当前不得以本 CR 为由宣称骨架已完成或放宽原阻塞。
